## 1. 目标、范围与判断依据

首页要让游客记住 Culvoy，并直接体验城市内容。高端感由品牌构图、真实城市素材和操作反馈共同形成。核心记忆点是“把一座城市排成自己的纪念票券”。

业务范围如下：

- Hero 使用居中的 Culvoy 品牌；保留文化、路线和口译三个核心入口。
- 城市 Ticket 完整生成器放在原首页口译介绍区位置。Hero 可提供通往该区的短入口，不复制第二套生成器。
- 首页商品、地图、公共日历、文化内容和独立 `/interpreting` 页面继续保留。
- 匿名访客可以预览和下载；购买、预约、登录和完成旅行都不是前置条件。
- Ticket 是纪念图，不承担门票、支付凭证或到访认证功能。
- 本轮交付文档，不生成品牌资产、不改代码、不改生产内容。

本文中的组件名、接口形状、动效参数和性能数字均为实施建议。视觉方向采用现有浅色、方正、编辑式品牌基础，具体参数在原型验证后定稿。

## 4. 具体改造方案

### 4.1 Hero：城市索引与品牌中心

Hero 采用居中品牌构图：Culvoy 是第一视觉层，城市图像是第二层，三个业务入口是第三层。保留足够的空间，但避免把标题、按钮和图片拆成重复卡片。

建议原型比较：

| 方向 | 静态结构 | 交互变化 |
| --- | --- | --- |
| A：城市索引 | 居中字标，下方是一条城市索引和三类功能入口 | 点击城市后切换照片及相关链接上下文 |
| B：城市图版 | 居中字标与一张大幅城市图版组合，入口沿版面底线分布 | 点击城市标签切换图版裁切与城市信息 |

主方向建议 A。两个原型必须在构图和操作方式上不同，不能只换颜色或字体。最终由真实素材、移动端可读性和操作发现率决定。

Hero 不放完整票券编辑表单。提供明确的 Make a city ticket 入口，滚动定位到原口译区的生成器；关闭减少动效时直接定位，不执行长距离平滑滚动。

导航入口保留真实路由 `/culture`、`/routes`、`/interpreting`。若调整 BOOK，需要先解决原方案与最近导航决定的差异，不能让 BOOK 默认代表免费路线预约。

### 4.2 Ticket 区：城市票券印制台

桌面布局为“操作区 + 大尺寸票面”；手机布局为“票面预览 + 分组输入 + 导出按钮”。选项和预览在同一流程内，避免来回打开多个弹窗。

票面建议包含：品牌、真实城市照片、城市名、日期、可选昵称、可选短句、纪念编号和城市公开文稿二维码。使用方正边缘、细裁切线和有限纸张层次，不把旋转、胶带和阴影应用到所有元素。

建议新增职责，文件名在实施时确定：

- `CityTicketPanel`：输入、状态和资源准备。
- `CityTicketPreview`：浏览器可访问预览。
- `ticket-template`：坐标、排版、配色和尺寸 token。
- `ticket-renderer`：字体、图片、二维码与 PNG 导出。

预览和导出必须共用票面数据与排版约束。浏览器 DOM 不直接作为任意 HTML 截图来源，以免预览和下载图的换行、比例不一致。

### 4.3 实时反馈与动效分镜

| 用户动作 | 页面反馈 | 建议实现 | 降级 |
| --- | --- | --- | --- |
| 进入生成区 | 显示完整可读票面；可选一次纸张落位 | GSAP，约 400～600 ms | 直接显示终态 |
| 选择城市 | 城市名、图片、二维码同步变更，保留输入 | 小范围套印过渡，约 200～300 ms | 即时切换 |
| 修改昵称或短句 | 实时排版与字数提示 | React 状态计算，无持续动画 | 相同功能 |
| 预览票面 | 可选轻量景深或指针倾斜 | 仅 fine pointer，角度建议不超过 2° | 手机静态，按钮操作完整 |
| 导出 | exporting → ready/error；成功回执持续可见 | 依据真实资源与渲染进度更新 | 不人为延迟导出 |

所有时长是原型建议。禁止为等待动画而阻塞下载。只有一个主交互机制，图片 hover 放大和持续鼠标光斑不作为主要成果。

### 4.4 状态、资源与隐私

状态至少覆盖：初始、无城市、资源加载、可预览、输入无效、导出中、下载成功、导出失败、媒体回退。

- 使用城市 slug 标识，名称和图片来自现有公开城市数据。
- 输入仅作为本地内存数据，默认不上传、不公开、不记入公共日志。
- 图片和字体准备完成再导出；跨域资源不可导出时给出明确原因与可用回退。
- 真实城市图像失效时显示文字版票券，不用无关照片伪装该城市。
- 纪念编号与预约、订单、用户 ID 完全分离；刷新后的编号规则需一致说明。
- 二维码只使用白名单内的公开城市地址，不拼接昵称和私人信息。
- 建议先采用单一票面比例。候选导出尺寸为 2400 × 1200 px，最终需经手机保存与实际图像检验后确定。
- 设计长昵称、长城市名和缺字字体的排版回退；限制单位需明确是字符、字素还是其他规则。

## 6. 测试方案

### 6.1 单元与组件测试

| 编号 | 用例 | 断言 |
| --- | --- | --- |
| H-T01 | 切换城市 | 图片、城市名、公开二维码目标同时更新；昵称保留 |
| H-T02 | 修改日期与长文本 | 格式合法、越界提示明确、票面边界不溢出 |
| H-T03 | 图片和字体失败 | 有可读回退，导出不会无限等待 |
| H-T04 | 连续点击下载 | 同一时刻只有一个导出任务，结束后可再次导出 |
| H-T05 | PNG 结果 | 尺寸、非空图像、关键票面字段和二维码正确 |
| H-T06 | 匿名与隐私 | 无登录跳转、无生成输入上传、无私人 ID |
| H-T07 | 焦点与关闭 | 键盘可达；如果采用弹层，Escape 关闭并恢复焦点 |

测试重点是行为和最终图像，不通过只 mock renderer 来宣称 PNG 导出可用。测试 fixtures 只用于隔离环境，不替换真实公开素材做生产展示。

### 6.2 真实浏览器流程

在本地 Docker 或隔离预览中，从首页开始执行：进入 Ticket → 选择城市 → 输入昵称、日期、短句 → 预览 → 下载 → 实际打开 PNG → 扫码检查公开目的地 → 回到首页访问商品、文化与口译。

另测图片请求失败、慢网络、键盘操作、手机触摸和减少动效。检查网络中是否出现不必要的输入上传，记录控制台异常和失败请求。没有真实下载与图像检查，只能标记为组件验证。

### 6.3 工程检查

未来实施后运行 site 的 TypeScript、只读 lint、`npm run test:ci`、build，以及文档链接检查与 `git diff --check`。提交后等待对应 SHA 的远程 CI；本轮文档不会声称该未来功能已通过这些检查。

## 7. 结果视觉校验与证据

### 7.1 检查矩阵

完整响应式矩阵使用 320、375、390、430、768、834、1280、1440、1920 CSS px；1024 px 额外检查桌面切换边界。截图必须记录高度、浏览器、deviceScaleFactor 和字体加载状态。

至少在 390 × 844、834 × 1112、1440 × 900 三个尺寸保存以下画面：

1. 改造前首页与原口译区。
2. 新 Hero 静态终态。
3. Ticket 默认、长文本、资源失败、导出成功。
4. reduced-motion 终态。
5. 下载 PNG 原图及其手机预览。

### 7.2 通过标准

| 项目 | 通过标准 |
| --- | --- |
| 品牌 | 首屏 Culvoy 明确，三个入口易辨；不靠三行窄标题撑满屏幕 |
| 记忆点 | Ticket 通过城市选择和导出形成完整动作，不能仅是图片装饰 |
| 排版 | 字号层级清晰，城市长名不裁切，英文按钮不挤成微字 |
